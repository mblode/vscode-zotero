Audited 2026-09-08. GitHub inventory: 28 issues, 14 pull requests, 72 issue/PR conversation comments, 5 submitted PR reviews, and 5 inline review comments, including closed history. Seven issues and three PRs were open at audit time. This records technical dispositions; it does not close discussions or promise that every possible bug is fixed.

## Marketplace reviews

The [Marketplace review page](https://marketplace.visualstudio.com/items?itemName=mblode.zotero&ssr=false#review-details) showed five ratings and three written reviews. All three written reviews were read: a March 2026 Zotero 8 compatibility request, a December 2020 brackets/focus complaint, and a January 2020 positive review. The release tests the newer Zotero 10 stack, documents brackets/minimization, and fixes asynchronous editor handling. It does not claim a separate Zotero 8 test or control of OS window focus.

## Root causes and decisions

The old extension used deprecated `request` and `request-promise`, looked up the active editor after the asynchronous picker returned, and issued overlapping delete/insert edits for replacements. PDF lookup ignored the configured port and assumed attachment paths were always strings. Citation lookup used editor word boundaries, which truncate valid keys. Extension host location was unspecified despite depending on a local desktop application.

The replacement keeps the small CAYW integration and uses bounded native HTTP(S). Its direct agent avoids proxy environment interference. It captures editor identity, document version, and selections before requesting a citation. If the original edit is no longer possible, clipboard recovery preserves the response. JSON-RPC uses the same configured origin and validates the response and attachment data. A local UI extension host matches the desktop service dependency.

This follows the documented [VS Code extension host model](https://code.visualstudio.com/api/advanced-topics/extension-host), [bundling guidance](https://code.visualstudio.com/api/working-with-extensions/bundling-extension), and [real extension-host testing](https://code.visualstudio.com/api/working-with-extensions/testing-extension). There is no browser entry point because the implementation needs the desktop Node host. No workspace code is loaded or executed.

## Verification

- All 63 unit/command regressions pass. The suite covers HTTP status errors, incomplete responses, timeout/abort, bounded response size, proxy variables, custom endpoints, JSON-RPC envelopes, attachments, selection replacement, clipboard recovery, multi-cursor edits, notebook fallback, duplicate requests, and diagnostics. Each test is executable with `npm test`.
- Extracted release VSIX passes real VS Code 1.84.2 and 1.136.1 tests on macOS: activation, commands, multiple selections, a hidden original editor, a still-visible original editor, changed-document recovery, empty picker response, HTTP 500, TeX output, and connection diagnostics.
- Current [Zotero 10.0.1](https://www.zotero.org/support/changelog) and [Better BibTeX 9.0.63](https://github.com/retorquere/zotero-better-bibtex/releases/tag/v9.0.63) were run in a disposable profile and data directory on macOS, with no personal library or sync account. A synthetic article and one-page PDF were imported. The native picker returned `[@Author:2026-test]`; selected-item requests returned Pandoc, biblatex, natbib, and Typst output. JSON-RPC readiness and PDF lookup succeeded on custom port 23129. Sanitized responses are in `test/fixtures/zotero-10.json`.
- The fixture checks actual current [CAYW](https://retorque.re/zotero-better-bibtex/citing/cayw/) and [JSON-RPC](https://retorque.re/zotero-better-bibtex/exporting/json-rpc/) behavior. PDF URI resolution was verified; automatic OS protocol launching was tested with a VS Code API stub, not an interactive default-handler change.
- CI exercises packaged VS Code on current Linux, macOS, and Windows runners, plus the minimum VS Code on Linux. See the exact successful run linked in the release record before inferring CI completion.
- No runtime dependencies remain. Retained build tools use current stable versions at audit time. `@types/vscode` intentionally remains 1.84.2: it defines the supported API floor and vsce rejects API types newer than `engines.vscode`. Node 24 LTS is the development/CI runtime; the bundle targets Node 18 for the minimum editor.
